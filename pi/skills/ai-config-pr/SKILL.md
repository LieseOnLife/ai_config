# AI Config Change → ai_config PR

Every AI config change is backed up in `LieseOnLife/ai_config` (`~/repos/ai_config`). When you change any file below, **open a PR there in the same task without asking.** The PR is part of "done", not a follow-up to offer.

## Path map

| Live location | Repo path |
|---|---|
| `~/.pi/agent/skills/<name>/` (omp and pi load these; `~/.agents/skills/<name>` is often a symlink here) | `pi/skills/<name>/` |
| `~/.pi/agent/{agents,extensions,prompts,scripts}/`, `AGENTS.md`, `<repo>.md`, `settings.json` | `pi/…` |
| `~/.pi/agent/mcp.json` | `pi/mcp.json`, **minus `.mcpServers.trajectory`** (see below) |
| `~/.omp/agent/{agents,extensions,lib,managed-skills,prompts,rules}/`, `AGENTS.md`, `config.yml`, `mcp.json` | `omp/agent/…` |
| `~/.omp/marketplaces.json`, `~/.omp/plugins/{installed_plugins,omp-plugins.lock}.json` | `omp/…` |
| `~/.claude/{agents,commands,hooks,scripts,skills,prompts}/`, `CLAUDE.md`, `settings.json`, `settings.local.json`, `package.json` | `claude/…` |
| `~/.claude/plugins/{installed_plugins,known_marketplaces}.json` | `claude/{installed_plugins,known_marketplaces}.json` (top level, no `plugins/`) |
| `~/.codex/{agents,hooks,rules,scripts}/`, `AGENTS.md`, `config.toml`, `hooks.json`; real dirs in `~/.agents/skills/` | `codex/…`, `codex/skills/` |
| `~/.config/zed/{settings,keymap}.json` | `zed/…` |
| `~/.config/grinch/grinch.js`, `~/.local/bin/open-gov` | `grinch/grinch.js`, `grinch/open-gov` |

Not backed up, so no PR: credentials (`auth.json`, `models-store.json`), `models.json`, caches, sessions, `*.db`, `skills/openspec-*` (regenerated by `setup.sh`), and `extensions/trajectory` (owned by the Trajectory installer). Skills from `~/repos/obsidian-vault-template/skills` belong to that repo, not this one.

**`mcp.json` and Trajectory:** the Trajectory installer adds a machine-specific `trajectory` server to `~/.pi/agent/mcp.json`. Back it up with `jq 'del(.mcpServers.trajectory)' ~/.pi/agent/mcp.json > pi/mcp.json`. When installing `pi/mcp.json` live, merge it so the live `trajectory` entry survives; never overwrite the live file.

If a path isn't in the map, check the matching `scripts/sync-*.sh` / `install-*.sh` before assuming it isn't backed up.

## Procedure

1. **Name one purpose per PR.** A PR changes one skill or one behavior. If you changed two unrelated things, open two PRs.

2. **Switch `gh` to `LieseOnLife`** (it owns the repo): note the active account from `gh auth status`, then `gh auth switch --user LieseOnLife`. Switch back at the very end (step 9). Pass `-R LieseOnLife/ai_config` to every `gh` command, because you may be running from another repo.

3. **Create a worktree from fresh `main`** (never commit on `main`):
   ```bash
   git -C ~/repos/ai_config fetch -q origin
   git -C ~/repos/ai_config worktree add ../ai_config-worktrees/<topic> -b saje/<topic> origin/main
   ```
   If the branch or worktree already exists, don't delete it; use `<topic>-v2`, `-v3`, and so on.

4. **Check for collisions.** `gh pr list -R LieseOnLife/ai_config --state open`, then `gh pr diff <n> -R LieseOnLife/ai_config --name-only` for any PR that looks related. If an open PR touches the same file, say so in your PR, or ask Saje whether to stack on it.

5. **Bring in the change, file by file.** **Don't run `sync-*.sh` or `install-*.sh`.** They rsync whole directories with `--delete`, so they would sweep unrelated drift into the PR (or wipe live edits). For each file you touched:
   1. Before editing anything, `diff -u <worktree file> <live file>`. The worktree side is `origin/main`.
   2. If you edited the **live** file, copy **live → worktree**. Any hunks you didn't write are earlier live-only edits: keep them and list them in the PR as "backing up live-only edits".
   3. If you edited the **worktree** file and the live file had live-only hunks, port your change into the live file instead of copying over it.
   4. Never decide the direction by mtime. The fresh worktree always looks newest.

6. **Update every copy of a duplicated file.** Port the *logical change* into each copy that exists on `main`. Never overwrite one copy with another wholesale, because copies differ on purpose: frontmatter, script paths (`~/.codex/` vs `~/.claude/` vs `~/.pi/agent/`), MCP tool names, footers, and Codex's `$skill-name` vs `/skill-name`. Known duplicate sets:
   - `pi/skills/<name>` ↔ `claude/skills/<name>` ↔ `codex/skills/<name>`
   - `pi/prompts/<name>.md` ↔ `omp/agent/prompts/<name>.md` ↔ `claude/commands/<name>.md` ↔ `codex/skills/<name>/SKILL.md`
   - `pi/agents/` ↔ `omp/agent/agents/`; `pi/extensions/` ↔ `omp/agent/extensions/`
   - `pi/AGENTS.md` ↔ `omp/agent/AGENTS.md` ↔ `claude/CLAUDE.md` ↔ `codex/AGENTS.md`

   Exceptions:
   - **Codex symlinks:** skills listed in `codex/skills-from-pi.txt` are symlinks to the pi skill, so leave `codex/skills/<name>` alone. If that file isn't on `main` yet, check open PRs (`git -C ~/repos/ai_config show origin/saje/codex-skill-symlinks:codex/skills-from-pi.txt`). If the skill is listed there, skip the Codex copy and mention that PR, to avoid a modify/delete conflict.
   - **New skills:** hand-written ones go in `pi/skills/` only, unless Saje asks for Claude or Codex copies. Skills created by omp `manage_skill` live in `~/.omp/agent/managed-skills/<name>/` and go in `omp/agent/managed-skills/<name>/`. Don't also copy them into `pi/skills/`, or omp loads them twice.

7. **Make it live.** Install the final files to their live locations (per step 5), so the change works now and not only after merge. Then tell Saje what reload it needs:
   - Skills: none
   - pi prompts and extensions: `/reload` or restart
   - omp `config.yml`, extensions, `mcp.json`, settings: restart
   - Codex hooks: restart, then review them in `/hooks`
   - `grinch.js`: Grinch menu → **Reload Config (⌘R)**

8. **Commit, push, open the PR:**
   - Commit message: `<emoji> <Area>: <what changed>`, matching `git log --oneline` on `main`.
   - PR body: follow the `create-pr` skill (blockquote TL;DR, change table, Code Walkthrough, Test Plan, 🤖 footer). Describe the whole diff against `main`.
   - **Never merge.** Saje merges.

9. **Post-push.** ai_config has no CI (no `.github/workflows`). `gh pr checks <url>` prints `no checks reported` and exits 1; that is expected. Run it once; don't `--watch` or spawn a PR watcher. The post-push protocol's review and comment steps still apply. Then switch `gh` back to the account you noted in step 2.

10. **Report** the PR URL, the live files you installed, the reload they need, and any collision or live-only drift you found.
